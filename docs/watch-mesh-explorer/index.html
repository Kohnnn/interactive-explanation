Source snapshot

Original companion tool for the Interactive Mechanical Watch route. It reads the same binary geometry that powers that page's WebGL core (watch_vertices.dat, watch_indices.dat) and exposes every named sub-mesh individually instead of as one assembled movement.

Asset handoff

Route-local index.html, css/explorer.css, and ES modules js/explorer.js + js/model-table.js. Three.js is reused from ../interactive-mechanical-watch/vendor/three/; geometry is fetched from ../shared/mechanical-watch/models/. No assets are duplicated into this folder.

Decoded format

The .dat pair is ciechanowski-style interleaved geometry: Float32 vertices at a 24-byte stride (position.xyz + normal.xyz), Uint32 indices. Each of the 85 named meshes owns two consecutive index blocks — a triangle block and a wireframe line block — covering the buffer with no gaps or overlap. The authoritative table is shared/mechanical-watch/js/watch.js; per-component ranges are captured in docs/mechanical-watch/decoded/manifest.json.

Framing note

Meshes are stored at their modeling origins, not assembled positions, so ~20% of parts (hands, date digits, keyless works, regulator index) sit far off the movement core. The camera frames on a robust core radius (clamped percentile of centroid reach) and recenters on any part when it is selected, so outliers stay inspectable.

Validation guidance

Run node tools/check-public-surface.mjs . and node tools/smoke-bundle.mjs . --route watch-mesh-explorer after edits. The smoke run expects the #viewport canvas, an 85-item mesh list, and a mounted #reference-footer.
