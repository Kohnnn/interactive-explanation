Stargazing Dashboard

Local route /interactive-explanation/stargazing-dashboard/ is an original Engineering Sandbox lab that builds a first-person topocentric sky dome. It provides a time and location engine, bundled star/constellation/meteor data, ephemeris-style planet positions, guided target navigation, and a telemetry HUD overlay. The shipped implementation renders stars, constellation figures, horizon guides, cardinal labels, and solar-system markers through a local Three.js scene, with live time, weather, display tuning, guided navigation, hover picking, and keyboard controls.

Source snapshot

This route does not mirror one published external article. It is a local original build created for the interactive-explanation collection and written specifically as a first-person stargazing dashboard.

  • The route uses neutral provenance handling because there is no single upstream article to reference.
  • The shell is the shared Engineering Sandbox lab variant for hero framing and metadata attribution.
  • Astronomy calculations follow standard low-precision algorithms based on Jean Meeus Astronomical Algorithms for Julian date, GMST/LST, equatorial-to-horizontal transforms, and sun/moon/planet positions.
  • Bright star positions come from a HYG/Yale-derived local subset bundled as route-local JSON data.
  • Constellation boundary figures and meteor shower data are authored from public reference knowledge into route-local JSON schemas.
  • Three.js r70 is vendored locally at ../ev/scripts/three.js and loaded before route scripts.
  • The route keeps stable module APIs for state, astronomy, catalogs, controls, scene rendering, and HUD updates while shipping the complete local implementation behind those contracts.

Asset handoff

  • stargazing-dashboard/index.html owns the route shell, hero, observation deck, dashboard grid, HUD panels, and control bench.
  • stargazing-dashboard/css/stargazing.css provides the dark night-sky theme, dashboard layout, panel styling, and responsive breakpoints.
  • stargazing-dashboard/js/astro.js computes Julian date, sidereal time, equatorial-to-horizontal transforms, and low-precision sun, moon, and planet positions.
  • stargazing-dashboard/js/state.js provides the state store and time driver for observer, time, layers, weather, display tuning, target selection, and camera look.
  • stargazing-dashboard/js/catalog.js loads and validates local star, constellation, and meteor-shower data and supplies magnitude, color, and line-resolution helpers.
  • stargazing-dashboard/js/controls.js implements pointer-drag and keyboard look controls that write azimuth and altitude into the state store.
  • stargazing-dashboard/js/scene.js owns the Three.js renderer, sky geometry, catalog refreshes, camera, atmosphere response, body markers, and canvas picking.
  • stargazing-dashboard/js/hud.js binds location, time, weather, layer, and display controls to the state store and renders live telemetry.
  • stargazing-dashboard/js/main.js bootstraps the route, validates scene startup, wires guided navigation and details, and exposes the ready or fallback state.
  • ../ev/scripts/three.js is a vendored copy of Three.js r70 loaded as a global script before route-local modules.
  • ../shared/engineering-sandbox.css and ../shared/engineering-sandbox.js provide the shared lab shell.
  • ../shared/public-footer.css and ../shared/public-footer.js provide the provenance footer.
  • stargazing-dashboard/data/stars.json, constellations.json, and meteor-showers.json provide the route-local catalogs.

Known deviations

  • Neutral provenance: there is no referenceUrl because this is an original local route, not an upstream replica. The footer is wired with data-reference-mode="neutral" and a provenance note.
  • Astronomy accuracy is naked-eye visual grade, not ephemeris-grade. Positions are sufficient for identifying bright stars, planets, and constellations by eye but are not suitable for telescope pointing or precise astrometry.
  • The weather panel is a sandbox, not a live weather feed. Cloud cover dims stars, seeing changes point-size shimmer, and light pollution caps the visible magnitude limit.
  • Three.js r70 is retained for compatibility, so the renderer uses its legacy PointCloud, LinePieces, addAttribute, and VertexColors APIs.
  • Astronomy is naked-eye visual grade and omits precision corrections needed for telescope control, navigation, or astrometry.
  • Meteor data currently feeds the HUD; meteor radiant markers are not drawn in the WebGL scene.

Validation guidance

  • Keep the route self-contained and subpath-safe; all assets must remain local to stargazing-dashboard/ or the shared shell paths (../shared/, ../ev/).
  • Run node tools/sync-route-metadata.mjs . after any manifest changes to keep pages.json in sync.
  • Run node tools/check-public-surface.mjs . after any content or structural changes to the route or docs.
  • Run node tools/smoke-bundle.mjs . --route stargazing-dashboard for route-specific WebGL, interaction, responsive, footer, and runtime checks.
  • Run npm run check and npm run unit after JavaScript changes.
  • Keep the JSON catalog schemas compatible with catalog.js validation and preserve relative data paths for subpath hosting.
  • The route body sets data-story-shell="engineering-sandbox" and data-story-variant="lab". Do not switch to the longform essay variant without updating the hero layout, navigation, and chapter expectations.
  • Set data-stargazing-ready="true" only after scene initialization succeeds; renderer setup failures must expose the fallback instead.
