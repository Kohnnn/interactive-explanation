Interactive Mechanical Watch

Local route /interactive-explanation/interactive-mechanical-watch/ is a dark-editorial recomposition of the mechanical-watch teardown. It reuses the live WebGL movement engine verbatim and wraps it in a route-local dark reading surface, then extends the article with a "From Pixels to Resin" prototyping case study.

Source snapshot

This route is a local sibling build derived from the existing mechanical-watch route inside the interactive-explanation collection. It keeps the interactive teaching content local and surfaces no upstream creator branding or original-page link on the public surface.

  • The public route uses neutral provenance handling; the original upstream article URL is intentionally not surfaced.
  • The shell uses the shared Engineering Sandbox longform family for hero framing, rail navigation, and mobile chapter behavior.
  • The original WebGL movement behavior remains intact through the shared engine; the resin chapter reuses its shared binary geometry through a route-local Three.js adapter.

Asset handoff

  • interactive-mechanical-watch/index.html owns the route shell, longform body, demo mounts, and the new resin section.
  • shared/mechanical-watch/js/watch.js is the live WebGL movement engine used by both watch routes; only its model request paths differ from the archived route-local copy.
  • shared/mechanical-watch/js/base.js is the shared Bartosz-family base runtime for sliders, drawers, and ArcBall controls.
  • shared/mechanical-watch/css/ holds the original light-surface styles the engine expects.
  • interactive-mechanical-watch/css/editorial-shell.css is the route-local dark-editorial override layer, loaded last.
  • interactive-mechanical-watch/js/exploded-view-three.js maps the shared movement geometry into the selectable Three.js resin exploder.
  • interactive-mechanical-watch/js/exploded-view.js owns the accessible component controls, detail state, and SVG fallback.
  • interactive-mechanical-watch/vendor/three/ holds the pinned Three.js module, orbit controls, and license.
  • shared/mechanical-watch/models/*.dat are the binary vertex/index buffers used by the original movement engine and route-local Three.js adapter.
  • interactive-mechanical-watch/images/generated/ holds the editorial divider art for the resin process sections.

Known deviations

  • The reading surface is intentionally dark while each WebGL drawer_container sits inside a light framed inset, because the engine's loading text and explainers assume a light backdrop.
  • A new "From Pixels to Resin" chapter extends the article with a resin-casting prototyping case study; it is additive and does not alter the original WebGL demos.
  • The resin chapter opens with a Three.js exploded view built from the movement's shared binary geometry; users can scrub depth, orbit, zoom, and select components for subsystem notes.
  • The canvas is pointer-only and hidden from assistive technology; DOM component buttons remain the keyboard surface, and the selectable SVG stays mounted if Three.js initialization fails.
  • Generated PNGs remain as later process dividers and the SVG fallback backdrop rather than the primary exploded-view interaction.
  • Provenance is neutral rather than linking the upstream original page.

Validation guidance

  • Keep the route self-contained and subpath-safe; route-specific assets remain under interactive-mechanical-watch/ and the common watch runtime remains under shared/mechanical-watch/.
  • Do not fork the shared watch.js or base.js engines; restyle through css/editorial-shell.css only.
  • Preserve generated chapter behavior by keeping major sections anchored with top-level h1 ids, and preserve every demo element id (the engine binds demos by id).
  • Run both node interactive-explanation/tools/check-public-surface.mjs . and node interactive-explanation/tools/smoke-bundle.mjs . --route interactive-mechanical-watch after edits.
