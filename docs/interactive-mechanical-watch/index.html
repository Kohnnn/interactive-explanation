Interactive Mechanical Watch

Local route /interactive-explanation/interactive-mechanical-watch/ is a dark-editorial recomposition of the mechanical-watch teardown. It keeps the shared WebGL movement engine unchanged, adds route-local keyboard and reduced-motion support, and places a linked "From Pixels to Resin" prototyping case study before the closing resources.

Source snapshot

This route is a local sibling build derived from the existing mechanical-watch route inside the interactive-explanation collection. It keeps the interactive teaching content local and surfaces no upstream creator branding or original-page link on the public surface.

  • The public route uses neutral provenance handling; the original upstream article URL is intentionally not surfaced.
  • The shell uses the shared Engineering Sandbox longform family for hero framing, compact chapter labels, rail navigation, and an immediately reachable mobile chapter bar placed after the hero.
  • The original WebGL movement behavior remains intact through the shared engine; a route-local adapter adds keyboard semantics and reduced-motion startup without duplicating simulation logic.
  • The resin chapter reuses shared binary geometry through a route-local Three.js adapter and links selected components back to the relevant lessons.

Asset handoff

  • interactive-mechanical-watch/index.html owns the route shell, longform body, demo mounts, and the new resin section.
  • shared/mechanical-watch/js/watch.js is the live WebGL movement engine used by both watch routes; only its model request paths differ from the archived route-local copy.
  • shared/mechanical-watch/js/base.js is the shared Bartosz-family base runtime for sliders, drawers, and ArcBall controls.
  • shared/mechanical-watch/css/ holds the original light-surface styles the engine expects.
  • interactive-mechanical-watch/css/editorial-shell.css is the route-local dark-editorial override layer, loaded last.
  • interactive-mechanical-watch/js/watch-parts.js is the canonical 71-part inventory shared by the accessible controller and Three.js renderer.
  • interactive-mechanical-watch/js/exploded-view-three.js maps canonical movement meshes and generated watchmaking geometry into the animated Three.js exploder.
  • interactive-mechanical-watch/js/exploded-view.js owns accessible playback and speed controls, component selection, incremental depth updates, lesson links, detail state, and SVG fallback.
  • interactive-mechanical-watch/js/legacy-watch-accessibility.js adapts the shared canvases, sliders, segmented controls, and playback controls for keyboard and reduced-motion use.
  • interactive-mechanical-watch/vendor/three/ holds the pinned Three.js module, orbit controls, and license.
  • shared/mechanical-watch/models/*.dat are the binary vertex/index buffers used by the original movement engine and route-local Three.js adapter.
  • interactive-mechanical-watch/images/generated/ holds the editorial divider art for the resin process sections.

Known deviations

  • The reading surface is intentionally dark while each WebGL drawer_container sits inside a light framed inset, because the engine's loading text and explainers assume a light backdrop.
  • A new "From Pixels to Resin" chapter extends the article before the closing resources; it is additive and does not alter the original WebGL demos.
  • The resin chapter opens with a 71-part Three.js exploded view. Canonical meshes cover the modeled movement components; 16 pivot-sensitive meshes preserve archived local offsets, flips, and ZYX rotation composition, while route-local procedural geometry supplies missing teeth, pinions, staffs, screws, dial markers, springs, case, crystal, and caseback.
  • The mechanism runs continuously with source-derived gear, escapement, balance, hand, calendar, rotor, and automatic-winding relationships at selectable 1×, 8×, and 60× speeds.
  • The Three.js canvas is pointer-only and hidden from assistive technology; DOM component buttons remain the keyboard surface, and a 71-target selectable SVG stays mounted if Three.js initialization fails.
  • The exploded view opens with an ordered three-step first-run guide (reassemble with depth, select a component, watch which layers move) because the section previously stated its goal without an explicit first action.
  • The exploded-view detail region is aria-atomic; renderDetail replaces the whole subtree, so partial announcements were otherwise possible.
  • Legacy teaching canvases and controls gain keyboard semantics through the route-local adapter while continuing to delegate to the shared runtime's existing handlers; y-only views advertise only effective keys and multi-slider demos expose unique names.
  • Reduced-motion preference pauses automatic startup but preserves explicit playback.
  • Generated PNGs remain as later process dividers and the SVG fallback backdrop rather than the primary exploded-view interaction.
  • Provenance is neutral rather than linking the upstream original page.

Validation guidance

  • Keep the route self-contained and subpath-safe; route-specific assets remain under interactive-mechanical-watch/ and the common watch runtime remains under shared/mechanical-watch/.
  • Do not fork the shared watch.js or base.js engines; restyle through css/editorial-shell.css only.
  • Preserve generated chapter behavior by keeping major sections anchored with top-level h1 ids, and preserve every demo element id because the engine binds demos by id.
  • Keep resin depth updates incremental so the component-list DOM and scroll position remain stable.
  • Targeted smoke coverage checks effective keyboard controls, unique slider names, mobile chapter placement and destination focus, reduced-motion startup, native legacy touch sliders, Three.js touch orbit, lesson links, and the 320px component-list layout.
  • Run both node tools/check-public-surface.mjs . and SMOKE_PORT=4174 node tools/smoke-bundle.mjs . --route interactive-mechanical-watch from the interactive-explanation/ directory after edits.
