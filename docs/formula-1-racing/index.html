Source snapshot

This route does not mirror one published external article. It is a local original build created for the interactive-explanation collection and written specifically around modern Formula 1 systems.

  • The public route uses neutral provenance handling because there is no single upstream article to reference.
  • The shell still uses the shared Engineering Sandbox longform family for hero framing, rail navigation, and mobile chapter behavior.
  • The interaction layer now follows the Bartosz-family pattern more closely by using local base.js controls and procedural canvas scenes.

Asset handoff

  • formula-1-racing/index.html owns the route shell, longform body, scene mounts, and control containers.
  • formula-1-racing/js/base.js is a local unmodified copy of the Bartosz-family base runtime and must be treated as-is.
  • formula-1-racing/css/base.css provides the slider, segmented-control, drawer, and canvas utility styling expected by the base runtime.
  • formula-1-racing/js/f1.js drives the procedural canvas scenes, state synchronization, and route-specific calculations.
  • formula-1-racing/css/f1.css adds Formula 1-specific colors, slider accents, and scene framing on top of the base runtime styles.

Current build

  • The route now ships a rotatable overview car, animated airflow, front-wing wake, floor, rear-wing, chassis, power, tyre, braking, track, racecraft, setup, weather, pit, and lap scenes.
  • The overview and aero chapters now use fuller pseudo-3D procedural geometry instead of flatter dashboard-style illustrations.
  • All 42 mounted controls now expose visible domain labels and matching accessible names while retaining the unmodified Bartosz-family controls.
  • The Floor and Diffuser chapter exposes live ride-height and pitch controls, one shared floor-health calculation, and visible suction, stability, and risk results.
  • Live floor health changes track-weighted sector scores, the speed trace, per-sector deltas, and the final lap summary.
  • The Tyres chapter carries compound, temperature, load, and stint condition into track-weighted sector scores, speed and braking traces, and tyre-attributed lap loss.
  • The Braking chapter now carries brake bias and energy recovery into a shared stability state, brake-demand-weighted sector loss, trace shape, and brake-attributed lap loss.
  • The final lap canvas now labels floor, tyre, and braking contributions beside the existing sector deltas and traces.
  • The scenes are procedural and explanatory rather than regulation-grade or telemetry-grade simulations.
  • Track selection, setup presets, live floor posture, live tyre condition, braking balance, power maps, and weather influence the final lap-builder scene. Pit timing remains a separate race-strategy calculation.

Keyboard interaction

  • Track, weather, lap-plan, and every shared segmented control are semantic radio groups with Arrow-key selection and synchronized checked state.
  • All slider and segmented-control mounts use data-control as the shared source for their visible labels and accessible names.
  • Shared sliders expose values plus Arrow, Home, and End keyboard behavior while their existing callbacks continue to update captions and canvases.
  • The two floor controls retain richer directional labels while preserving the same unmodified Bartosz-family slider runtime and keyboard contract.
  • Reduced-motion preference stops perpetual scene repainting while state changes still repaint the visible canvas.

Progress and next plan

  • Completed: all 42 control names, centralized floor, tyre, and braking states, track-weighted lap coupling, per-sector and per-system contribution labels, independently attributed losses, and focused keyboard smoke coverage.
  • Model boundary: live floor, tyre, and braking states are teaching inputs layered over the setup; they are not telemetry, CFD, a suspension solver, a brake-by-wire simulation, or a full tyre-energy model.
  • Next: keep the single-lap model stable; add another contribution only when a chapter gains an independently attributable loss.
  • Deferred: pit strategy stays outside the single-lap model unless the route adds a stint or race-time view.

Validation guidance

  • Keep the route self-contained and subpath-safe; all assets should remain local to formula-1-racing/ or the shared shell.
  • Do not edit formula-1-racing/js/base.js unless the route intentionally forks the Bartosz-family engine.
  • Preserve generated chapter behavior by keeping major sections anchored with top-level h1 ids.
  • Run node tools/check-public-surface.mjs . and node tools/smoke-bundle.mjs . --route formula-1-racing from the interactive-explanation/ directory after edits.
  • The control-label, causality, and lap-contribution passes completed JS syntax, parity JSON, metadata, public-surface, focused route smoke, and engineering-longform family smoke checks.
  • Responsive browser checks passed at 390px and 320px with 42 matching visible and accessible names, 50px slider hit areas, single-column floor controls, no horizontal overflow, measurable tyre and braking lap losses, and compact contribution labels that fit the 320px canvas.
  • The earlier all-route smoke run completed route baselines but exceeded the local ten-minute command window before its final smoke phase; focused route and affected-family runs completed separately.
